  <action>
    Create `backend/routers/newsvendor.py` with an APIRouter prefix `/api/infer` or `/api` (let's use `/api/newsvendor` or `/api` matching forecast router prefix `/api`).
    Define endpoint: `GET /api/newsvendor` accepting query parameters:
    - `item_id`: str (required)
    - `start_date`: Optional[str]
    - `end_date`: Optional[str]
    - `unit_cost`: Optional[float] (override supplier cost)
    - `sell_price`: Optional[float] (override sell price)
    - `salvage_value`: Optional[float] (override salvage value)
    
    Logic details:
    1. Load future window and items via `store.load()`. Validate `item_id` exists.
    2. Retrieve base item metadata (`supplier_cost`, `sell_price`, `item_type`).
    3. Determine unit economics:
       - Cost $c$ = `unit_cost` if provided else `base_supplier_cost`.
       - Price $p$ = `sell_price` if provided else `base_sell_price`.
       - Salvage $s$ = `salvage_value` if provided else (`0.40 * c` if `item_type == 'hotel'` else `0.15 * c`).
    4. Filter future window by `item_id` and optional date range (`start_date`, `end_date`). If no dates provided, aggregate or return daily breakdown (support daily records and aggregate summary). Let's return daily breakdown AND summary totals or support aggregation across the selected range.
    5. Predict P10, P50, P90 for each date using `model_store.predict(item_df)`.
    6. For each date (or aggregated period), compute:
       - Critical Fractile $CR = \frac{p - c}{p - s}$. (Validate $p > c$ and $p > s$, handle edge cases where $p \le c$ or denominator $\le 0$).
       - Quantile interpolation from P10 (0.10), P50 (0.50), P90 (0.90) to find demand $Q^*$ at $CR$.
       - Expected profit and costs.
    7. Register router in `backend/main.py`.
  </action>
